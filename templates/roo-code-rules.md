## 开发规则

- 先阅读相关文件，再提出修改计划。
- 修改前说明会改哪些文件，以及为什么。
- 只做当前任务需要的最小改动。
- 保持现有代码风格。
- 不引入新依赖，除非明确说明收益和风险。
- 修改后给出测试命令和验证结果。

## 禁止操作

- 不要自动提交 Git。
- 不要自动 push。
- 不要删除用户未明确要求删除的文件。
- 不要修改生产环境配置。
- 不要读取、输出或提交密钥、token、cookie、私钥。
- 不要改动 `.env`、证书、部署脚本，除非任务明确要求。

## 输出格式

每次重要改动前输出：

1. 理解到的任务。
2. 计划修改的文件。
3. 风险点。
4. 验证方式。

完成后输出：

1. 修改摘要。
2. 测试结果。
3. 仍需人工确认的事项。
